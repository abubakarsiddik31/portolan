# G1 and G2 — what the evidence supports

**Date:** 2026-11-09
**Frozen commit:** `98d8af4cd800f7720da76ab7ea6acf3b933fab03`
**Model:** `scripted` (no provider key was configured)
**Decision:** [ADR-005](./DECISIONS.md#adr-005--g1g2-are-not-passed-release-gate-stays-closed)

---

## 1. The short version

The compiler, the repair loop, the write safety layer, and the MCP surface
work end to end on the held-out fixtures. The **economic gates** — G1's
oracle-relative win and G2's drift rate under real use — are **not measured**.

| Gate | What it requires | What we have | Result |
|---|---|---|---|
| G0 | perfect ops vs `agent-browser`: ≥3x steps, ≥5x cost, 2 providers | nothing (no provider keys) | **not run** |
| G1 | held-out compile ≥60% of oracle's $ win, yield ≥50%, break-even K≤3, 2 providers | 100% yield on compiled candidates; no oracle $; one scripted provider | **not passed / not measured** |
| G2 | ≥80% auto-repair within 2 runs; 0 duplicate writes | 3/3 scripted repairs, 0 duplicates, 3/3 drift-day success | **not a valid sample** |
| R4 | G0, G1, G2 recorded in `DECISIONS.md` | ADR-005 records that they are not passed | **open** |

The release gate stays closed. The harness is ready for the run that would
decide it.

## 2. What was measured

## 3. What the evidence does not support

- **No oracle cost comparison.** The N=3 table has no arm D-oracle row, so the
  "≥60% of the oracle's $ win" clause is unmeasured.
- **No two-provider run.** Every row is `provider: scripted`, `model:
  scripted`. ADR-003 says a gate must hold on two providers; this is zero
  real providers.
- **No real model.** The scripted model cannot fail in the way a model fails.
  Success 100% is a harness property, not a result.
- **No statistical drift sample.** Three ops and one run cannot establish
  ≥80% repair. The filter and paginate drifts are semantic — the op still
  succeeds but returns the wrong rows — and the drift script does not catch
  them.
- **Zero duplicates is structural, not stressed.** The run has one write and
  no idempotency-key retry. The forced-failure test (T2.24) is the real
  evidence for no double-charge, and it covers one store checkout.
- **No WebArena run.** The images were not pulled; the held-out apps are our
  own fixtures, not Magento or GitLab.

---

## 4. Threats to validity

| Threat | Effect |
|---|---|
| scripted model | success and cost are not model results |
| one run | no variance estimate; the CIs are template-level only |
| three drift ops | repair rate is anecdotal |
| small fixtures | the compiler may not generalize to real app complexity |
| no oracle rows | the G1 comparison has no denominator |
| no provider keys | G0 and the two-provider clause are untested |
| one write | duplicate-write evidence is thin outside T2.24 |

---

## 5. What would change the decision

The next run must produce, on the frozen commit:

1. **Arms A, B, C, D-oracle** on the 16 held-out templates, with **two
   providers** and a **model-Y transfer** run.
2. **N=3** per template, with billed usage and cost, not scripted zeros.
3. **Oracle rows** so G1's "≥60% of the oracle's $ win" has a denominator.
4. **A drift run with real models**, including the semantic filter and
   paginate failures, and a write that is retried with an idempotency key.
5. **A canary pass rate over 7 days** for the release criterion R5.

Decision rules, from the plan:

- **G1 <60% of the oracle's win** → narrow to human-recorded maps.
- **G2 <80% repair, or any duplicate write** → reads-only release, or stop.
- **Both pass on two providers** → R4 can be marked; the release gate opens.

Until then, no document, README, or launch asset may say G1 or G2 passed.
